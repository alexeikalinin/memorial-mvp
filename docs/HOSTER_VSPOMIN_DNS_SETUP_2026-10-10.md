# Настройка vspomin.ai в Hoster.by — 10 октября 2026

## Что было до настройки

Домен зарегистрирован и активен до 27.05.2028. В управлении доменом выбран хостинг HOSTER.BY с ns1.hoster.by / ns2.hoster.by. В разделе DNS-хостинг зоны vspomin.ai не было; публичный DNS возвращал SERVFAIL/REFUSED. Старый сайт memorial-mvp.vercel.app и backend Railway остаются действующими.

## Как настроено

1. Авторизованный кабинет Hoster.by → Мои услуги → Домены. Выбран только vspomin.ai (ID домена 777630).
2. Домены и DNS → DNS-хостинг → Подключить домен → выбрать vspomin.ai → Подключить домен.
3. Hoster.by предупредил, что DNS-серверы изменятся на **u1.hoster.by / u2.hoster.by**. После подключения vspomin.ai появился со статусом АКТИВЕН; кабинет подтвердил отправку запроса на изменение Name Servers.
4. Открыт Расширенный редактор новой зоны (ID141952). До добавления список записей был пуст. В этой зоне не было MX/TXT/CNAME для переноса; другие домены и почтовые услуги не изменялись.
5. Добавлены две записи по актуальной рекомендации Vercel для текущего проекта:

| Тип | Поле ДОМЕН | Значение | TTL |
|---|---|---|---|
| A | @ | 216.198.79.1 | 1 час / 3600 |
| A | @ | 64.29.17.1 | 1 час / 3600 |

**Важная особенность редактора:** в поле ДОМЕН для корня вводить `@`. Если ввести `vspomin.ai` без завершающей точки, редактор добавляет суффикс и получает `vspomin.ai.vspomin.ai.`. Первая запись была создана так, затем исправлена через «Редактировать» на `@`; итоговая таблица показывает `vspomin.ai.` для обеих записей, ошибочная запись не осталась.

6. После каждого сохранения кабинет показывает уведомление успешного добавления/обновления; закрыть уведомление крестиком перед следующим действием.
7. Обе итоговые A-записи подтверждены таблицей кабинета и ответом authoritative DNS u1.hoster.by.

## Проверка и текущий результат

Прямой запрос к u1.hoster.by возвращает оба правильных IP. Публичные resolver-ы ещё не видят новую делегацию; HTTPS проверка пока остановилась на невозможности разрешить домен. Vercel verify пока возвращает invalid configuration и старые ns1/ns2.hoster.by. Это не подтверждённый запуск нового сайта: нужно дождаться применения NS-запроса/обновления кэша, затем повторно проверить DNS, Vercel и HTTPS.

В управлении доменом повторно подтверждены выбранный расширенный редактор и u1.hoster.by / u2.hoster.by. Снимок итоговых записей: `artifacts/domain-migration/hoster-dns-final.jpg`.

DNS TTL записей3600 — не обещание, что делегация обновится за час. Если делегация не изменится, проверить управление доменом/статус заявки и обратиться в Hoster.by; без разрешения владельца сообщения поддержке не отправлялись.

## Что не менялось

Работающий Vercel deployment, код production, frontend API URL, Railway env, Google callbacks, текущие платежи, другие домены. www/api/app поддомены пока не настроены. Настройки входа переключать только после готовности соответствующего API-домена, Google Console и CORS.

## Как повторить проверку

В Hoster.by: Домены и DNS → DNS-хостинг → vspomin.ai → Расширенный редактор; должны быть ровно две A-записи выше. В Домены → vspomin.ai → Управление DNS проверить u1/u2.hoster.by после применения заявки. В Vercel → проект → Settings → Domains → vspomin.ai проверить Valid Configuration и сертификат. После этого проверить главную https://vspomin.ai и https://vspomin.ai/app/login.

## Откат

Старый сайт продолжает работать без переключения DNS обратно. Если требуется отменить новую делегацию, Домены → vspomin.ai → Управление DNS вернуть прежние ns1.hoster.by / ns2.hoster.by; это вернёт исходную неработающую DNS-конфигурацию домена, а не восстановит сайт на vspomin.ai. Не отключать новую DNS-зону и не удалять записи без необходимости. Поскольку работающий сайт/БД не изменялись, восстановления данных для отката этого этапа не требуется.
