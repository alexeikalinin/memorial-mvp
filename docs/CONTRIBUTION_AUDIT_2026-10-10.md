# Приглашения, модерация и голосовые воспоминания — аудит 10.10.2026

## Область проверки
Текущая локальная версия кода, API-тесты на изолированной SQLite и подмена OpenAI для проверки контракта транскрибации. Это не подтверждение работы опубликованной версии, реального микрофона или качества распознавания. Production данные не изменялись. Для полного допуска нужен контрольный сценарий на staging с настоящим аудио и действующим OpenAI.

## Как работает сейчас
- Владелец/редактор создаёт приглашение; гость открывает `/app/contribute/:token` на production (Vite base), без регистрации. Frontend строит ссылку от текущего origin с учётом base.
- Можно написать текст вручную или записать голос, получить текст, исправить его и отправить. Заголовок необязателен.
- API проверяет токен, принадлежность мемориалу, срок действия и разрешение `add_memories`. Запись получает `status=pending`, `source=invite`, имя автора берётся из label приглашения. Присланный клиентом `source=voice_invite` игнорируется схемой: голосовые и ручные записи не различаются в БД.
- Владелец видит заявки на вкладке «Воспоминания». Первичная загрузка и проверка каждые 30 секунд реализованы в MemorialDetail. Email/push для этого сценария не обнаружены; владелец должен открыть страницу.
- Только фактический владелец может получить очередь, одобрить или отклонить запись. Отклонение удаляет её. До одобрения запись исключена из публичного API и контекста RAG.
- После одобрения запись публична (с учётом доступа к мемориалу), запускается Celery-задача индексации.
- Микрофон записывается браузерным MediaRecorder. Аудио отправляется на FastAPI `/api/v1/ai/transcribe`, затем через OpenAI SDK в `audio.transcriptions.create(model="whisper-1")`. Ключ — `OPENAI_API_KEY` сервера. Fish Audio/ElevenLabs отвечают за другие функции голоса, не за эту транскрибацию.
- Исходное аудио не сохраняется как воспоминание: сохраняется только текст. Сервер удаляет временный файл транскрибации.

## Риски до выпуска
1. **Расходы и доступ:** `/ai/transcribe` не требует пользователя или валидного приглашения; клиент не передаёт invite_token. Доступен платный вызов без связи с мемориалом. Есть общий IP rate limit, но нет отдельной квоты аудио/владельца/приглашения. Нужны проверки с реально включённым limiter.
2. **Размер и формат:** весь файл читается в память, верхнего ограничения размера и длительности нет. `allowed_audio` объявлен, но не проверяется. Ошибка провайдера возвращает сырой текст исключения. Нужны валидация и безопасные сообщения.
3. **Язык:** frontend отправляет language в multipart, backend принимает его как query. Значение из формы игнорируется, по умолчанию `ru`. ContributePage вообще не передаёт текущий язык. Автотест подтверждает: multipart `en` → провайдер получает `ru`.
4. **Safari/iPhone:** MediaRecorder выбирает реальный формат сам, но Blob и имя файла принудительно объявлены WebM. При записи MP4 возможна неверная маркировка. Нужен выбор поддерживаемого MIME и реальный тест iOS.
5. **Жизненный цикл микрофона:** нет cleanup при уходе со страницы во время записи; нет ограничения длительности, прослушивания аудио и отдельной кнопки повторить транскрибацию после ошибки.
6. **Индексация после модерации:** при ошибке постановки Celery-задачи approve silently пропускает её, синхронного fallback и сообщения владельцу нет. Видимость текста подтверждается отдельно от готовности векторного поиска. Возможность DB fallback в чате не подтверждает исправность индексации.
7. **Авторство и спам:** label обозначает приглашение, а не проверенную личность автора. Пересланная ссылка даёт тот же доступ. uses_count — счётчик, не лимит. Нет защиты от повторной отправки на уровне idempotency и ограничения длины content (кроме min_length=1).

## Тесты перед production

### P0 — обязательны для выпуска этого сценария
- [ ] Владелец создаёт ссылку, гость открывает её в чистом инкогнито на vspomin.ai; ссылка и refresh работают с `/app/`, нет запроса регистрации, localhost и старого домена.
- [ ] Ручной текст → сохранение → подтверждение отправки → очередь владельца → одобрение → публичное отображение → доступность факта в AI. Отдельно отклонение: исчезновение из очереди, отсутствие в публичной выдаче и AI.
- [ ] Pending недоступен гостю, другому владельцу и редактору; нельзя одобрить/удалить чужую запись подменой ID.
- [ ] Неверный, истёкший, отозванный токен; токен другого мемориала; `add_memories=false`; истечение/отзыв после открытия страницы — сохранение запрещено.
- [ ] Реальная запись и распознавание RU и EN на Chrome desktop/Android и Safari iPhone; проверить фактический MIME, HTTPS, разрешение микрофона, остановку и редактирование текста.
- [ ] Отказ микрофона, отсутствие устройства, тишина, пустой/битый/неподдерживаемый файл, слишком большой файл и длинная запись — понятная ошибка без зависания и без лишнего списания.
- [ ] Нет ключа OpenAI, timeout, 429, 5xx, недоступная сеть: текст пользователя сохраняется в форме, доступны повтор и ручное добавление.
- [ ] Закрытие/переход страницы во время записи отключает микрофон; после возврата можно записать заново.
- [ ] Транскрибация без действующего доступа заблокирована; отдельные лимиты и квоты реально работают под нагрузкой, ограничивают память и расходы.
- [ ] Worker/Redis/Qdrant отключены при одобрении: текст не теряется, индекс восстанавливается, ошибка наблюдаема; после восстановления AI находит одобренную запись.
- [ ] Двойное нажатие, повтор HTTP после обрыва, две вкладки: нет дублей; две одновременные модерации дают согласованный результат.
- [ ] Приватный мемориал остаётся приватным; отзыв ссылки закрывает все предоставленные ею действия.

### P1 — качество и эксплуатация
- [ ] Счётчик очереди обновляется при загрузке и через 30 секунд; длинные тексты, много заявок, offline/reconnect, загрузочные ошибки.
- [ ] Различать реальный пустой список и ошибку загрузки очереди; проверить ожидания уведомлений владельца вне сайта.
- [ ] Имена, даты, акценты, тихий голос и фоновый шум; пользователь всегда может исправить текст перед отправкой.
- [ ] RU/EN подписи и ошибки, доступность с клавиатуры/экранным диктором, мобильная ширина 320/390, длинный заголовок.
- [ ] native share, отмена share, clipboard fallback; повторная пересылка ссылки в мессенджерах.
- [ ] HTML/script в тексте, очень длинный/пробельный текст, Unicode; безопасный вывод и ограничение размера.
- [ ] Временные файлы удаляются при успехе и ошибке; аудио/токены/содержание не попадают в ненужные логи; понятное согласие на передачу записи OpenAI.
- [ ] Расходы и мониторинг: ошибки/задержка Whisper, заявки/модерация, застрявшие embeddings, бюджет и оповещения.
- [ ] Staging smoke после deploy; сверить версию backend/frontend, CORS, ключ OpenAI, reverse proxy лимиты, backup и восстановление памяти/приглашений.
