# Готовая запись вместо синтеза благодарственной речи

Для явно запрошенной сохранённой благодарственной речи API сначала проверяет привязанную запись в новой таблице `memory_audio_replies`. Если запись есть и голос включён, ответ содержит полный сохранённый текст и защищённую ссылку на исходный MP3. Не вызываются embeddings, LLM, TTS и photo animation. Остальные ответы и речи без привязанной записи используют прежний путь. Добавлена формулировка «Расскажи благодарственную речь для гостей».

Запись хранится как `bytea` в существующей БД, без публичного bucket, внешней AI-обработки и включения аудио в Git. Для одного небольшого файла это сохраняет источник и запись вместе с резервной копией БД. Таблица создаётся через существующий startup `create_all` (не требует изменений существующих таблиц); foreign key каскадно удаляет запись при удалении памяти. Выдача через подписанную ссылку на 12 часов с отдельным audience; подпись/ID/срок/статус approved проверяются на каждом запросе. Поддерживаются HTTP Range и private/no-store. Обычные проверки права на чат и голос остаются до выбора записи.

Тесты: полный HTTP chat→URL→MP3 byte equality, Range, source, отсутствие внешних AI; ID mismatch/invalid/expired/wrong-audience tokens; unapproved recording недоступна. Исходная запись проверена локальным FFmpeg на полное декодирование. Привязка пользователя и hash receipt хранятся в SESSION_LOG.md, а не здесь. Подробности выпуска/CI — SESSION_LOG.md.
