# Ложный отказ при опечатке в одобренном воспоминании — 16.10.2026

## Причина и подтверждение

Владелец сообщил: после одобрения истории вопрос «расскажи про рыбалку» получает ответ об отсутствии информации.

Проверено read-only на production: запись1494 принадлежит мемориалу318, status=approved, есть автор и embedding_id. Трассировка реального retrieval с заменой генерации диагностикой показала1494 среди10контекстных записей (3039символов), вместе с автором и source_memorial_id318. Значит, модерация, сохранение в БД и retrieval работают.

В исходном тексте есть опечатка «незабыаемо». Модель сформировала правильный ответ, но в JSON-цитате исправила слово на «незабываемо» и добавила точку. Сервер требовал точную подстроку исходника и вернул стандартный no-evidence ответ, даже не вызывая независимую проверку фактов. На точно этой записи проблема воспроизведена3/3раза: отдельно и с9вымышленными отвлекающими историями.

## Исправление

Сервер делит исходный текст на нумерованные фрагменты. Модель выбирает memory_id и segment_ids, а сервер получает доказательства из оригинального текста по этим номерам. Модель больше не должна перепечатывать доказательство и случайно исправлять опечатки/пунктуацию. Ответ может исправлять обычное правописание, но не имена, числа, отрицания или факты.

Сохраняются обязательные проверки: существующая запись, целочисленные и существующие номера фрагментов, не более3номеров на источник, отсутствие дубликатов, независимая проверка ответа по точному исходному доказательству. Для старого формата quote сохранена строгая дословная проверка — fuzzy matching не добавлен. Тексты в БД не изменяются, повторное одобрение или переиндексация не нужны.

## Границы проверки и откат

Не запускался HTTP-чат, который отправил бы все остальные частные воспоминания318во внешний AI. Для пути retrieval использована безопасная диагностика без генерации, для генерации — именно предоставленная запись и вымышленные отвлекающие истории. Исходный текст других записей не менялся и не публиковался в логах теста. Исправление не связано с голосами/Fish/квотами/схемой БД. Откат исходного кода к844d213 возвращает прежнее поведение без миграции данных.
