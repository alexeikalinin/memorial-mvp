# Ложные отказы при наличии воспоминаний — 16.10.2026

## Подтверждённая причина

На одобренной записи мемориала 319 генератор правильно составил биографический ответ с двумя существующими фрагментами источника. Независимая модель проверки фактов вернула `supported=false`, после чего сервер показал стандартный ответ об отсутствии информации. Запись есть в SQL; отсутствие embedding_id не мешает общему вопросу «что ты помнишь о себе?», потому что overview использует approved SQL archive напрямую.

После явного согласия владельца на проверку через OpenAI проведены диагностический прогон до исправления и контроль после его запроса исправить ошибку. До: генератор supported=true, verifier=false, sources=[]. После: генератор supported=true, verifier=true, source memory_1495. Данные не менялись; текст частного воспоминания здесь не приводится.

## Изменение

Уточнены правила независимой проверки:

- «Я» в ответе аватара — субъект мемориала; «я» в исходном авторском воспоминании — рассказчик. Это разные уровни текста.
- Биография от третьего лица может быть пересказана от первого без добавления нового факта. Связанные предложения проверяются вместе с source_text, чтобы правильно разрешать «он/она».
- Автору не нужно быть участником рождения, школы или других явно описанных биографических фактов. Перестановка имени и фамилии не меняет личность.
- Обычная коррекция орфографии/рода/падежа не является новым фактом. Проверка оценивает факты, а не стиль или кавычки JSON. Требования к естественной форме ответа остаются у генератора.
- Сохраняются запреты на неверные даты, новые события, приписывание событий автора/родственников субъекту мемориала и выдуманных участников.

При отклонении ответа verifier пишет отдельное диагностическое предупреждение с IDs источников; приватные тексты, имена и вопрос в этом предупреждении отсутствуют. Формат API и данные не меняются. Не добавлены дополнительные модельные запросы в обычный чат.

Ранее опубликованное исправление 318edbf (нумерованные source segments вместо перепечатывания цитат) сохраняется. Оно устраняет другой подтверждённый ложный отказ — когда модель исправляет опечатку при цитировании, а exact-match проверка отвергает цитату.

## Проверки

- 48 offline targeted passed, 9 live cases по умолчанию skipped.
- Полный backend: 346 passed / 9 skipped в release checkout (127.21s); 348 passed / 9 skipped в исходном checkout (129.20s). Fatal flake8 и diff-check пройдены.
- 9/9 opt-in real OpenAI evaluations passed: RU/EN biography, name order, spelling; отрицательные wrong year, wrong sport, narrator event, invented companion, relative event.
- Полная реальная генерация RU/EN на вымышленных биографиях: 2/2 успешны.
- Исходный случай 319 после правки: реальный генератор и независимый verifier приняли ответ, источник1495 сохранён.
- Новые HTTP regressions проходят реальный путь API→approved unindexed SQL memory→генератор→сборка точных evidence→verifier→ответ со source и без suggest_memory. OpenAI в этих HTTP tests подменён, внешние retrieval/embedding вызовы запрещены.

Повторяемый реальный synthetic eval (использует только вымышленные константы; требует ключ OpenAI из окружения/backend/.env):

```sh
cd backend
RUN_LIVE_GROUNDING=1 DATABASE_URL=sqlite:////tmp/grounding-eval.db USE_S3=false .venv/bin/python -m pytest tests/test_memory_biography_grounding.py -k live -q
```

Независимый verifier остаётся моделью, поэтому все возможные формулировки не гарантированы этим конечным набором проверок. Новая диагностика отличает его отказы от проблем получения источников. Полные тесты и статус публикации дополняются в SESSION_LOG.md.
