# Вспоминай — мобильное приложение

React Native + Expo SDK 58 + Expo Router. Это отдельный клиент существующего FastAPI API: свои экраны, зависимости и сборки, но **тот же аккаунт, данные и серверные права**, что у веба. Веб-интерфейс не меняется. Для мобильного Google-входа добавлен отдельный серверный модуль `backend/app/api/mobile_auth.py`, временная таблица попыток входа и небольшое подключение в существующем callback.

## Структура

```text
mobile/
  src/app/          # Только маршруты Expo Router
  src/screens/      # Экраны приложения
  src/components/   # Мобильные компоненты, запись/плееры, формы
  src/api/          # Типизированный клиент общего API
  src/auth/         # Сессия, Keychain/Keystore
  src/media/        # Подготовка голосовой записи
  src/theme.ts     # Мобильные токены бренда
  assets/          # Утверждённый логотип и иконка тестового приложения
  tests/           # Контракт API, сессия, запись WAV
  integration/     # Проверки общего сервера и двух интерфейсов
```

Мобильное приложение не импортирует React-компоненты, CSS или зависимости веба. Корневые npm-скрипты продолжают работать с `frontend/`. Native `ios/`/`android/` генерируются Expo и не коммитятся. Для мобильной части используйте Node **24** (`.nvmrc`); установленный на машине Node 25 не входит в поддерживаемые Expo версии.

## Запуск

```sh
cd mobile
nvm use
npm ci
cp .env.example .env.local
npm start
```

В `.env.local` установите `EXPO_PUBLIC_API_URL` равным **тому же** полному API URL, который использует нужная веб-версия. Пример формата: `https://YOUR_BACKEND/api/v1`. Значение публичное: ключи OpenAI/Fish/S3 и SECRET_KEY здесь запрещены. После смены окружения перезапустите Expo с очисткой кеша: `npx expo start --clear`.

Для локального API:

- iOS Simulator: `http://localhost:8000/api/v1`;
- Android Emulator: `http://10.0.2.2:8000/api/v1`;
- физический телефон: LAN-адрес компьютера в той же Wi-Fi сети; сервер должен слушать этот адрес, либо используйте доступный HTTPS API.

`localhost` на настоящем телефоне указывает на телефон, а не на Mac. Для удалённого API требуется HTTPS. В native-сборке токен хранится в SecureStore и привязан к адресу API. В браузерном предпросмотре токен хранится только в памяти: обновление вкладки потребует повторного входа. Пароль не сохраняется. Смена API сбрасывает сессию. Настройки подключения видны только в dev-сборке.

Для браузерного предпросмотра: `npm run web`. Это проверка общей React Native логики через RN Web, **не доказательство работы нативного микрофона, камеры, системных переходов и подписи**. Симуляторы требуют установленных Xcode / Android SDK. Используемые модули относятся к Expo SDK; совместимость конкретного Expo Go на телефоне нужно проверить перед запуском. Для собственного app scheme и платформенной проверки используйте development build.

## Что реализовано

- Вход и регистрация email/password в существующем сервисе.
- «Мои страницы»: только страницы с owner/editor/viewer доступом; поиск, создание, профиль.
- Обзор человека; воспоминания с авторством и датой события; фото/видео/аудио, системный выбор файлов, просмотр и плееры.
- Голосовая запись с предпрослушиванием. Native AAC/MP4 отправляется как `audio/mp4` / `.mp4`; браузерная запись преобразуется в PCM16 WAV. Это соответствует текущему списку разрешённых расширений сервера.
- AI-чат через существующий endpoint, опциональное аудио и источники. История диалога локальна текущему экрану.
- Родные списком из существующих связей, хронология.
- Редактирование имени/биографии owner/editor; публичность и модерация владельцу; приглашение поделиться историей.
- Публичная страница по `/m/:id`, гостевое предложение воспоминания на рассмотрение. Семейный архив скрыт при отсутствии ACL; сервер остаётся окончательным источником прав.
- Обновление по фокусу, возврату приложения и pull-to-refresh; защита от устаревших ответов после выхода/смены аккаунта.

## Границы первой версии

- Google-вход реализован через системную auth-сессию в собственной native/development сборке. Expo Go и RN Web preview этот поток не поддерживают: кнопка объясняет ограничение. Для реального входа нужно опубликовать серверное дополнение; автоматические тесты используют вымышленные ответы Google.
- Загрузка материалов не объединяет аудио/фото с отдельным текстовым воспоминанием в новую модель данных. Голосовая запись сохраняется в материалах; автоматическая транскрипция в мобильном клиенте ещё не подключена.
- Полное редактирование дерева, оформления и настройка клона голоса остаются на сайте. Переход не переносит сессию автоматически — в браузере может потребоваться вход.
- Доступ к аккаунту/подписке через сайт; native purchases не реализованы.
- Universal Links/App Links для HTTPS QR ещё не опубликованы: нужны окончательные store identifiers, подпись и доменные association-файлы. Пока существующий QR продолжает открывать веб. Custom scheme для собственной dev-сборки: `vspomin:///m/ID`. Обработчик входящих ссылок понимает существующие `/app/m/ID` QR и нормализует их в мобильный `/m/ID`; это не заменяет настройку доменных association-файлов.
- Нет полного offline-режима, межустройственных черновиков, push и live-sync. Сохранённые данные общие при подключении к одному API; обновление по запросу/фокусу.
- Логотип экспортирован из существующих approved SVG без перерисовки. Тестовая иконка использует квадратную композицию; окончательную иконку магазинов нужно проверить отдельно в малых размерах.
- Пока старый API возвращает все публичные страницы, «Мои страницы» уточняет ACL запросами деталей с ограничением параллельности 4. Для большого каталога нужен отдельный серверный scope; это не менялось ради изоляции веба.


Эти проверки используют in-memory SQLite и временные загрузки. Они подтверждают отдельные сессии одного аккаунта, двустороннее создание материалов, изображения/WAV/MP4-видео/MP4-аудио, права viewer/другого аккаунта и гостевую модерацию. Embedding-задачи и почта отключены; реальные внешние AI-провайдеры не вызываются.

### Два реальных интерфейса на одном тестовом сервере

В отдельных терминалах из корня:

```sh
backend/.venv/bin/python mobile/integration/preview_server.py
VITE_API_URL=http://localhost:8000/api/v1 npm --prefix frontend run dev -- --host 127.0.0.1 --port 5188
```

Соберите mobile web с `EXPO_PUBLIC_API_URL=http://localhost:8000/api/v1` и раздайте `mobile/dist` на `http://localhost:8081` (для прямых переходов `/m/ID` нужен SPA fallback либо Expo dev server).

```sh
node mobile/integration/browser-smoke.cjs
```

Этот сценарий использует существующий Playwright из `e2e/node_modules` (`npm ci --prefix e2e` при необходимости). Входит через оба интерфейса, создаёт страницу и воспоминание в mobile, читает на сайте, добавляет на сайте и читает в mobile; проверяет file picker → upload → веб-галерею и транспорт чата. Скриншоты — `mobile/qa/` (не Git).

Тестовый аккаунт: `mobile-qa@example.com` / `MobileTest123!`; только одноразовая вымышленная локальная БД. Сервер запускается исключительно на loopback. Его чат использует явно тестовый ответ, а не реальный AI; тарификация обходится только demo-флагом одноразового аккаунта. Это не production-конфигурация.

См. `QA.md` для фактически выполненных проверок и оставшихся устройств.

## Google-вход

Кнопка «Продолжить с Google» открывает системную авторизацию, возвращается в `vspomin://oauth/callback` и завершает вход в тот же аккаунт. Пароль Google и client secret приложение не получает. Для имеющегося Google-профиля/подтверждённого email используется существующий User ID.

Серверные endpoints: `POST /api/v1/auth/mobile/google/start` и `POST /api/v1/auth/mobile/google/exchange`; callback Google остаётся прежним `/api/v1/auth/google/callback`. Нужны уже существующие серверные `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `PUBLIC_API_URL`. Дополнительные iOS/Android client IDs при этом способе не требуются. Адрес callback должен совпадать с уже разрешённым в Google Console.

Попытка действует5минут. Приложение создаёт случайный verifier и S256 challenge; callback выдаёт отдельный одноразовый handoff code, а не JWT в ссылке. Только пара verifier+handoff code обменивается на сессию. Таблица `mobile_google_attempts` хранит challenge и hash кода, очищает истёкшие попытки при новых входах; claim/exchange одноразовые с условным SQL update. Нельзя подключить неподтверждённый email, отключённый или уже связанный с другим Google-профилем аккаунт.

Для physical-device Google test установите development build со scheme `vspomin`. Expo Go не может зарегистрировать собственную OAuth callback scheme. Тестируется сначала на iPhone12ProMax, затем iPadAir, Android позднее. Наличие Apple Developer paid membership не нужно для локального Xcode-run на своём устройстве с бесплатной подписью, но Xcode должен быть установлен. Backend addition пока не опубликован.
